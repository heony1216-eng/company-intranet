# 주간 업무보고 발표 모드 설계

작성일: 2026-09-18 (2026-09-21 수정: 내용 전부 표시, 조작 바 제거, 표시할 모니터 지정, 카드형 디자인, 행별 발표 아이콘)

## 목적

주간 회의에서 주간 업무보고를 앞에서 발표할 때, 보고서를 PPT 슬라이드 쇼처럼 전체화면으로 넘기며 볼 수 있게 한다.
파일을 따로 만들지 않고 인트라넷 안에서 바로 발표한다. 보고서 내용은 한 글자도 잘리지 않고 모두 보여야 한다.

## 사용 흐름

1. 주간 업무보고 목록 툴바의 **발표** 버튼을 누른다 (인쇄 버튼 옆). 한 사람 보고서만 발표하려면 그 행의 관리 칸 맨 왼쪽 **발표 아이콘**(인쇄 아이콘 왼쪽)을 누른다. 체크할 필요가 없다.
2. 목록에서 체크한 보고서가 있으면 그 항목만 바로 발표한다 (인쇄와 같은 규칙).
3. 체크한 것이 없으면 "발표할 주차 선택" 창이 뜬다. 현재 연·월 필터 안의 주차가 건수와 함께 나열되고 최신 주차가 기본 선택된다.
4. 모니터가 2대 이상이면 같은 창에 **표시할 모니터** 목록이 함께 나온다 (아래 "모니터 지정" 참고). 체크한 항목만 발표할 때도 이 경우에는 창을 거친다.
5. **발표 시작**을 누르면 전체화면 슬라이드 쇼가 열린다.

## 슬라이드 구성

- **표지**: "2026년 9월 3주차 주간업무보고" 제목과 발표 순서(팀 · 이름 목록). 이름을 클릭하면 그 사람 슬라이드로 이동한다.
- **사람별 슬라이드**: 상단에 주차(작게, 파랑) · 이름(아주 크게) · 팀 · 직급(회색 칩). 본문은 업무마다 **섹션**: 번호 배지와 큰 제목, 그 아래 업무내용을 줄마다 글머리표로 풀어 쓴 항목들. 상자·표는 쓰지 않고 여백으로 구분한다. 항목 오른쪽에 진척률 막대 게이지와 숫자(100% 초록, 50% 이상 파랑, 그 외 주황, 배경 상자 없음), 비고가 있으면 항목 아래 작은 글씨. 글은 줄이지 않고 전부 표시한다.
- **자동 분할**: 숨김 레이어에서 실제 슬라이드와 같은 폭·부품으로 섹션을 그려 항목·제목·상자 높이를 잰 뒤(섹션 높이 = 제목 + 항목 합 + 간격), 한 장의 본문 높이에서 여유 48px를 뺀 만큼을 넘기 전에 다음 장으로 나눈다. 항목은 쪼개지 않는다. "1 / 2"로 표시하고, 섹션이 이어지면 제목을 다시 그리고 "(계속)"을 붙인다. 답답하지 않도록 한 장을 끝까지 채우지 않는다.
- **금주 업무 · 특이사항**: 그 사람의 마지막 장에서 섹션 아래에 파란 세로선이 있는 섹션으로 표시한다. 자리가 없으면 별도 장으로 뺀다.
- **사진**: 첨부 이미지가 있으면 사진 슬라이드(한 장에 최대 4장)가 뒤에 붙는다.
- **끝**: "발표가 끝났습니다" 슬라이드.
- 발표 순서는 팀 → 이름 가나다순이다.
- 안전장치: 잰 값과 실제가 어긋나거나 한 행이 한 장보다 길면 그 장의 내용을 CSS zoom으로 줄여 모두 보이게 한다(AutoFit).

## 화면과 조작

- 화면에는 슬라이드만 보인다. 검은 배경 위에 16:9 흰색 슬라이드가 화면에 맞춰 꽉 차고, 상단·하단 바는 없다.
- 슬라이드 오른쪽 아래에 PPT 페이지 번호처럼 "3 / 12"를 작게 표시한다.
- 마우스를 움직이면 오른쪽 위에 전체화면 · 종료 버튼이 2.5초 동안만 나타나고, 멈추면 커서와 함께 사라진다.
- 다음: →, ↓, Space, Enter, PageDown, 화면 오른쪽 절반 클릭. 이전: ←, ↑, PageUp, Backspace, 화면 왼쪽 절반 클릭.
- 처음/끝: Home / End. 전체화면 전환: F 키 또는 버튼. 열릴 때 자동으로 전체화면을 시도한다.
- 종료: Esc (전체화면이면 첫 Esc는 전체화면 해제, 둘째 Esc가 종료) 또는 종료 버튼.
- 무선 프레젠터(클리커)는 PageUp/PageDown을 보내므로 그대로 동작한다.

## 모니터 지정

- 크롬·엣지의 창 관리 API(Window Management)를 쓴다. `screen.isExtended`로 모니터가 2대 이상인지 권한 없이 확인하고, 그럴 때만 시작 창에 "표시할 모니터" 목록을 보여준다.
- 목록은 `getScreenDetails()`로 가져온다. 처음 호출하면 브라우저가 "창 관리" 권한을 묻는다. 거부되면 안내 문구와 "다시 불러오기"를 보여주고, 그대로 시작하면 현재 모니터에 띄운다.
- 각 모니터는 이름과 해상도, 내장 화면 · 주 모니터 · 현재 창 표시를 함께 보여준다. 기본 선택은 지난번에 고른 모니터(localStorage `weeklyPresentation.screenLabel`), 없으면 현재 창이 있는 모니터다.
- 고른 모니터는 `requestFullscreen({ screen })`으로 넘긴다. 브라우저 창이 그 모니터로 옮겨져 전체화면이 되고, 발표를 끝내면 원래 자리로 돌아온다. F 키·전체화면 버튼도 같은 모니터를 쓴다.
- 사파리·파이어폭스·모바일처럼 지원하지 않는 환경에서는 목록이 나오지 않고 기존처럼 현재 모니터에서 발표한다.

## 디자인

- 슬라이드는 1280×720 기준으로 그린 뒤 화면 크기에 맞춰 통째로 확대/축소한다. 위쪽에 파란 띠를 둔다. 85인치 TV처럼 큰 화면에서 멀리서 보는 상황을 기준으로 한다.
- 글자 크기 위계(1280 기준): 이름 52px 굵게 → 업무 제목 34px 굵게 → 본문 26px(줄 간격 1.625) → 비고 21px. 주차 표시 20px. 단계 차이를 크게 두어 한눈에 구분되게 한다.
- 여백: 슬라이드 안쪽 64px/48px, 머리글 아래 32px, 섹션 사이 32px, 항목 사이 8px. TV 오버스캔을 고려해 페이지 번호는 가장자리에서 안쪽으로 둔다.

## 파일 구조

- `src/utils/weeklyPresentationSlides.ts`: 보고서 배열 → 슬라이드 배열 변환 순수 함수 (정렬, 잰 높이 기준 자동 분할, 사진 URL 추출).
- `src/components/worklog/WeeklyPresentation.tsx`: 전체화면 오버레이. 높이 측정 레이어, 키보드 · 클릭 · 전체화면 · 크기 조정 처리, 슬라이드 종류별 렌더링, AutoFit.
- `src/pages/WeeklyWorkLogPage.tsx`: 발표 버튼, 발표 시작 창(주차 선택 + 표시할 모니터), 발표 화면 연결 (기존 목록 데이터 재사용, 새 조회 없음).
- `src/utils/screens.ts`: 창 관리 API 감싸기 (지원 여부, 모니터 목록, 설명 문구, 마지막 선택 기억).

## 예외 처리

- 필터 안에 보고서가 없으면 발표 버튼 비활성.
- 전체화면 요청이 거부되면 무시하고 창 안에서 발표한다.
- 업무가 하나도 없는 보고서도 사람 슬라이드 1장은 만든다.
- 높이 측정 전(첫 렌더링)에는 사람마다 한 장씩 만들고, 측정이 끝나면 곧바로 다시 나눈다. 슬라이드 수가 바뀌어도 현재 위치는 범위 안으로 보정한다.

## 확인 방법

프로젝트에 자동 테스트 환경이 없으므로 로컬 브라우저에서 실제 데이터로 주차 선택 → 슬라이드 분할 → 잘림 검사(scrollHeight 대비) → 키보드 · 클릭 이동 → 조작 버튼 자동 숨김 → 종료를 직접 확인한다. `tsc --noEmit`으로 타입을 검사한다.
